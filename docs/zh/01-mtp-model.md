# 01 · MTP 模型架構（Multi-Token Prediction）

> 本文件對應程式碼：`mtp/model.py`

## 1. 為什麼用「多步預測」而不是只預測明天

股價預測最常見的做法是「next-day return」單點預測：輸入過去 N 天，輸出隔天報酬。
問題在於——單點預測的訊號非常嘈雜，隔天報酬幾乎由雜訊主導，模型很難學到可交易的結構。

**MTP（Multi-Token Prediction）** 借鏡語言模型的做法（如 DeepSeek-V3 的 MTP）：
讓模型一次輸出**同一時間點的多個未來步驟**，本專案為

```
T+1  ·  T+3  ·  T+5  ·  T+10
```

四個不同天期的累計對數報酬。這樣做的三個好處：

1. **多期共振濾網**：只有當短、中、長期的方向一致（例如 T+3 沒有破底、T+5 與 T+10 都看漲）才會產生交易訊號，等價於用模型自己輸出的「路徑」做基本面式的確認，大幅降低雜訊進場。
2. **隱含時間結構**：四個輸出共享同一個 backbone，模型被迫學到「短線動能 → 中期趨勢」的遞延關係。
3. **直接對齊策略天期**：交易主波段設定為 10 天，正好等於最長的預測天期，模型預測 horizon 與持倉假設一致。

## 2. 輸入 / 輸出

| 項目 | 形狀 | 說明 |
|---|---|---|
| 輸入 `x` | `[B, 250, 16]` | 250 個交易日（約一年）的 16 維技術特徵 |
| 輸出 | `[B, 4]` | T+1 / T+3 / T+5 / T+10 的累計對數報酬 |

輸出是**對數累計報酬**，推論時以 `exp(pred) - 1` 還原成百分比報酬。

## 3. 架構圖

```
              x: [B, 250, 16]
                     │
        ┌────────────▼─────────────┐
        │  input_proj              │  Linear(16 → 768)
        │  LayerNorm + GELU        │  特徵投影到 d_model 維度
        └────────────┬─────────────┘
                     │
        ┌────────────▼─────────────┐
        │  Learnable Positional    │  可學習位置編碼 (max 1000 steps)
        │  Encoding (nn.Parameter) │
        └────────────┬─────────────┘
                     │
        ┌────────────▼─────────────┐
        │  TransformerEncoder      │  10 層 pre-norm encoder
        │  d_model = 768           │  nhead = 16, FFN = 4x, GELU
        │  dropout = 0.2 (train)   │
        └────────────┬─────────────┘
                     │  h: [B, 250, 768]
        ┌────────────▼─────────────┐
        │  pooling fusion          │  mean(h) + h[:, -1, :]
        │  (全局 + 最新步)          │  = [B, 768]
        └────────────┬─────────────┘
                     │
     ┌───────┬───────┼───────┬──────────┐
     ▼       ▼       ▼       ▼          │
  head_d1 head_d3 head_d5 head_d10      │  各為 Linear(768→128)→GELU→Linear(128→1)
     │       │       │       │          │
     └───────┴───────┴───────┴──────────┘
                     │
              y_hat: [B, 4]
```

## 4. 關鍵設計說明

### 4.1 `input_proj`（輸入投影）
16 維特徵量綱差異大（報酬是 1e-2 量級、bias 是 0~1 量級），先過一層 `Linear → LayerNorm → GELU`，
把特徵拉到同一個表示空間，也能讓後續 LayerNorm 的梯度更穩定。

### 4.2 可學習位置編碼
`nn.Parameter(torch.randn(1, 1000, d_model) * 0.02)`，直接加在投影後的序列表示上。
使用可學習版本而非正弦版本，原因是日線資料的「位置」資訊（越近的天數越重要）由模型自行決定權重更有效。

### 4.3 `norm_first=True`（Pre-Norm）
10 層深的 encoder 若用 Post-Norm 容易訓練不穩，Pre-Norm + 殘差連接可讓深層網路穩定收斂。
`dim_feedforward = 4 * d_model = 3072`。

### 4.4 pooling：`mean + last`
- `mean(h)`：整段 250 天的**全局結構**（長期趨勢、波動體質）
- `h[:, -1, :]`：**最新一天**的狀態（當下動能）

兩者相加而非只有取最後一步，可避免「只看最後一天導致忽略長期脈絡」的問題；相加而非 concat 是為了控制參數量（單一 head 即可）。

### 4.5 四個獨立預測頭
每個 horizon 有一個 2 層 MLP head（`768 → 128 → 1`）。
不共享 head 的原因：T+1 的預測目標接近雜訊，T+10 則帶有明確的趨勢成分，兩者的回歸難度與量級都不同，共享 head 會讓短天期梯度污染長天期。

> **Checkpoint 相容性提醒**：head 的屬性名稱固定為 `head_d1` / `head_d3` / `head_d5` / `head_d10`，
> 與權重檔的 key 對應。若修改 `horizons`，請重新訓練。

## 5. 參數量

| 設定 | 值 |
|---|---|
| d_model / nhead / layers | 768 / 16 / 10 |
| Transformer encoder | ≈ 85M |
| input_proj + heads | ≈ 1.2M |
| **總計** | **≈ 86M（FP32 權重檔約 288 MB）** |

若要在單張 8GB VRAM 上訓練，可將 `d_model=384, nhead=8, num_layers=6`（約 21M 參數），
於 `mtp-train --d-model 384 --layers 6` 指定。
